# Lステップ構築手順：測量機器販売の受注導線

## 目的

測量機器販売における LINE 公式アカウント / Lステップの受注導線を、以下 3 つのメニューを中心に構築します。

| メニュー | 役割 |
| --- | --- |
| 商品を探す | 測量機器のカテゴリ検索 |
| 見積依頼 | 受注前の問い合わせ・見積受付 |
| 注文する | 既存顧客・型番指定の注文受付 |

本手順では、ユーザーが「商品を探す」から検討を始め、「見積依頼」で商談化し、既存顧客や型番確定済みの顧客は「注文する」からスムーズに受注できる状態を目指します。

---

## 1. 全体設計

### 1.1 想定するユーザー導線

```text
LINE 友だち追加
  ↓
リッチメニュー表示
  ├─ 商品を探す
  │   ├─ 商品カテゴリ選択
  │   ├─ 新品 / 中古 / 消耗品の選択
  │   └─ 見積依頼へ誘導
  ├─ 見積依頼
  │   ├─ 要件ヒアリング
  │   ├─ 予算・納期確認
  │   └─ 担当者対応へ通知
  └─ 注文する
      ├─ 型番・数量入力
      ├─ 納品先・希望納期入力
      └─ 在庫確認 / 受注処理へ通知
```

### 1.2 構築する主要パーツ

- リッチメニュー
- 回答フォーム
- シナリオ配信
- タグ管理
- 友だち情報欄
- 自動応答メッセージ
- 担当者通知

---

## 2. リッチメニュー設計

### 2.1 メインメニュー構成

まずは 3 分割または 6 分割のリッチメニューを作成し、受注に直結する 3 導線を目立たせます。

| ボタン名 | アクション | 遷移先 |
| --- | --- | --- |
| 商品を探す | 商品カテゴリ検索を開始 | カテゴリ選択メッセージ |
| 見積依頼 | 見積フォームを開く | 見積依頼フォーム |
| 注文する | 注文フォームを開く | 注文受付フォーム |

### 2.2 6 分割にする場合の推奨配置

| 位置 | メニュー | 目的 |
| --- | --- | --- |
| 左上 | 商品を探す | 新規検討者のカテゴリ検索 |
| 中上 | 見積依頼 | 受注前の相談・見積獲得 |
| 右上 | 注文する | 既存顧客・型番確定者の注文受付 |
| 左下 | 消耗品・部品 | バッテリー、三脚、プリズム等の追加注文 |
| 中下 | 修理・点検 | アフターフォロー窓口 |
| 右下 | 担当者に相談 | チャット・電話相談への誘導 |

この MD では、上段 3 メニューを中心に構築します。

## 3. 「商品を探す」構築手順

### 3.1 商品カテゴリを決める

測量機器販売では、顧客が用途や機器名で探せるようにカテゴリを整理します。

| カテゴリ | 主な対象 |
| --- | --- |
| トータルステーション | 土木測量、建築測量、境界測量 |
| GNSS / GPS 測量機 | 基準点測量、ICT 施工、広域測量 |
| レーザーレベル | 建築、内装、水平出し |
| オートレベル | 土木、建築、一般測量 |
| 3D スキャナー | 点群計測、出来形管理、BIM / CIM |
| ドローン測量関連 | 空撮、写真測量、点群作成 |
| 測量ソフトウェア | CAD、出来形管理、点群処理 |
| 三脚・プリズム・ポール | 周辺機器、追加購入 |
| バッテリー・充電器 | 消耗品、保守部品 |
| 中古・整備済み品 | 価格重視、短納期希望 |

### 3.2 Lステップでカテゴリ選択メッセージを作成する

1. Lステップ管理画面で **シナリオ配信** または **テンプレート** を開く。
2. 「商品カテゴリ選択」というテンプレートを作成する。
3. カルーセル、ボタン、クイックリプライのいずれかでカテゴリを表示する。
4. 各カテゴリ選択時に、対応するタグを付与する。
5. 最後に「見積依頼へ進む」ボタンを設置する。

### 3.3 付与するタグ例

| ユーザー操作 | 付与タグ |
| --- | --- |
| トータルステーションを選択 | 興味：トータルステーション |
| GNSS / GPS を選択 | 興味：GNSS |
| レーザーレベルを選択 | 興味：レーザーレベル |
| 3D スキャナーを選択 | 興味：3Dスキャナー |
| 中古・整備済み品を選択 | 興味：中古機器 |

### 3.4 カテゴリ選択後の案内文例

```text
ご希望のカテゴリを確認しました。
在庫状況・価格・納期は機種や構成により変わるため、詳しい内容は見積依頼からお問い合わせください。

以下からお進みください。
・見積依頼をする
・担当者に相談する
・別の商品カテゴリを探す
```

## 4. 「見積依頼」構築手順

### 4.1 見積依頼フォームを作成する

Lステップの回答フォームで「測量機器 見積依頼フォーム」を作成します。

#### フォーム項目

| 項目 | 入力形式 | 必須 | 保存先 |
| --- | --- | --- | --- |
| 会社名 | テキスト | 必須 | 友だち情報：会社名 |
| 担当者名 | テキスト | 必須 | 友だち情報：担当者名 |
| 電話番号 | 電話番号 | 必須 | 友だち情報：電話番号 |
| メールアドレス | メール | 任意 | 友だち情報：メールアドレス |
| 希望商品カテゴリ | 選択式 | 必須 | 友だち情報：希望カテゴリ |
| メーカー希望 | 選択式 | 任意 | 友だち情報：メーカー希望 |
| 新品 / 中古 | 選択式 | 必須 | 友だち情報：商品状態 |
| 使用用途 | 複数選択 | 必須 | 友だち情報：使用用途 |
| 希望納期 | 日付 / 選択式 | 任意 | 友だち情報：希望納期 |
| 予算感 | 選択式 | 任意 | 友だち情報：予算感 |
| 備考 | 長文 | 任意 | 友だち情報：相談内容 |

#### メーカー希望の選択肢例

- トプコン
- ソキア
- ライカ
- ニコン・トリンブル
- その他
- 未定・相談したい

#### 使用用途の選択肢例

- 土木測量
- 建築測量
- 境界測量
- ICT 施工
- 3D 計測
- ドローン測量
- その他

### 4.2 見積依頼完了時のアクション

フォーム送信後、以下の処理を設定します。

1. タグ「見積依頼あり」を付与する。
2. 希望カテゴリに応じた興味タグを付与する。
3. 担当者へ通知する。
4. ユーザーへ自動返信する。
5. 必要に応じて商談フォロー用シナリオに登録する。

### 4.3 自動返信メッセージ例

```text
見積依頼を受け付けました。
内容を確認のうえ、担当者より在庫・価格・納期についてご連絡いたします。

お急ぎの場合は、このトークに「至急」と送信してください。
```

### 4.4 担当者通知メッセージ例

```text
【新規見積依頼】
会社名：{{会社名}}
担当者名：{{担当者名}}
電話番号：{{電話番号}}
希望カテゴリ：{{希望カテゴリ}}
メーカー希望：{{メーカー希望}}
新品 / 中古：{{商品状態}}
用途：{{使用用途}}
希望納期：{{希望納期}}
予算感：{{予算感}}
相談内容：{{相談内容}}
```

## 5. 「注文する」構築手順

### 5.1 注文受付フォームを作成する

既存顧客や型番が決まっている顧客向けに、注文内容を正確に受け取るフォームを作成します。

#### フォーム項目

| 項目 | 入力形式 | 必須 | 保存先 |
| --- | --- | --- | --- |
| 会社名 | テキスト | 必須 | 友だち情報：会社名 |
| 担当者名 | テキスト | 必須 | 友だち情報：担当者名 |
| 電話番号 | 電話番号 | 必須 | 友だち情報：電話番号 |
| 商品名または型番 | テキスト | 必須 | 友だち情報：注文商品 |
| 数量 | 数値 | 必須 | 友だち情報：注文数量 |
| 希望納品日 | 日付 | 任意 | 友だち情報：希望納品日 |
| 納品先住所 | 長文 | 必須 | 友だち情報：納品先住所 |
| 請求書宛名 | テキスト | 任意 | 友だち情報：請求書宛名 |
| 支払い方法 | 選択式 | 任意 | 友だち情報：支払い方法 |
| 備考 | 長文 | 任意 | 友だち情報：注文備考 |

### 5.2 注文フォームの注意書き

フォーム冒頭に以下を記載します。

```text
こちらは正式な受注前の注文受付フォームです。
在庫・納期・金額を確認後、担当者より正式な受注内容をご連絡いたします。
```

### 5.3 注文完了時のアクション

1. タグ「注文受付あり」を付与する。
2. タグ「既存顧客」または「注文見込み」を付与する。
3. 担当者へ注文内容を通知する。
4. ユーザーへ受付完了メッセージを送信する。
5. 在庫確認後に手動で正式受注へ進める。

### 5.4 自動返信メッセージ例

```text
ご注文内容を受け付けました。
担当者が在庫・納期・金額を確認のうえ、正式な受注内容をご連絡いたします。

内容に変更がある場合は、このトークにそのままご返信ください。
```

### 5.5 担当者通知メッセージ例

```text
【注文受付】
会社名：{{会社名}}
担当者名：{{担当者名}}
電話番号：{{電話番号}}
商品名 / 型番：{{注文商品}}
数量：{{注文数量}}
希望納品日：{{希望納品日}}
納品先：{{納品先住所}}
請求書宛名：{{請求書宛名}}
支払い方法：{{支払い方法}}
備考：{{注文備考}}
```

### 6.1 タグ設計

## 7. シナリオ配信設計

### 7.1 見積依頼後フォロー

| 配信タイミング | 内容 | 目的 |
| --- | --- | --- |
| 即時 | 受付完了メッセージ | 安心感の提供 |
| 1 日後 | 測量機器選定の確認ポイント | 検討促進 |
| 3 日後 | 新品・中古・リースの比較案内 | 選択肢提示 |
| 7 日後 | 導入事例・キャンペーン案内 | 商談化 |

### 7.2 注文受付後フォロー

| 配信タイミング | 内容 | 目的 |
| --- | --- | --- |
| 即時 | 注文受付完了 | 受付確認 |
| 在庫確認後 | 納期・金額の案内 | 正式受注化 |
| 納品後 7 日 | 使用状況確認 | 初期不安の解消 |
| 納品後 30 日 | 消耗品・予備品案内 | 追加注文獲得 |
| 納品後 6 か月 | 点検・校正案内 | アフターフォロー |

## 10. 推奨する初期公開範囲

最初からすべての機能を作り込むよりも、以下の順番で公開すると運用しながら改善しやすくなります。

1. リッチメニューを公開する。
2. 「商品を探す」のカテゴリ選択を公開する。
3. 「見積依頼」フォームを公開する。
4. 「注文する」フォームを公開する。
5. 担当者通知を運用に乗せる。
6. 見積依頼後フォローを開始する。
7. 注文後フォロー、消耗品提案、点検案内を追加する。

## 11. 最小構成の完成イメージ

```text
リッチメニュー
  ├─ 商品を探す
  │   ├─ トータルステーション
  │   ├─ GNSS / GPS
  │   ├─ レーザーレベル
  │   ├─ 3D スキャナー
  │   └─ 中古・整備済み品
  ├─ 見積依頼
  │   └─ 回答フォーム送信 → 見積依頼ありタグ → 担当者通知
  └─ 注文する
      └─ 回答フォーム送信 → 注文受付ありタグ → 担当者通知
```

この最小構成を先に完成させることで、測量機器販売の新規相談、見積受付、既存顧客からの注文受付を LINE / Lステップ上で一元化できます。
